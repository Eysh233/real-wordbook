## 2. D1 · GUI 技术栈（**需要你选择**）

| 方案 | 优点 | 缺点 | 新增依赖 | 适配本需求 |
| --- | --- | --- | --- | --- |
| **A. PyQt5 5.15.9**（推荐） | 已安装、零安装成本；`QPainter` 可精确画手绘荧光笔/斜线；QSS 全量换肤；`QPropertyAnimation` 做 spring 近似；高 DPI 成熟；`QGraphicsBlurEffect` 可做半透明工具条；信号槽天然支持"AI 线程 → UI"；打包生态成熟 | Qt5 已停止功能更新；GPL/商业双授权（个人自用无碍）；样式表调试不如浏览器 DevTools | 无 | ★★★★★ 全部需求可实现，含"纸页/装订脊/笔触"这类自绘 |
| B. PySide6 | 官方 LGPL 授权更宽松；Qt6 支持更好、渲染更清晰；API 与 PyQt5 高度相似（迁移成本低） | 需 Python ≥3.9 → 必须新装解释器（3.12），重装全部依赖，环境迁移有风险 | 新 Python + PySide6（~120 MB） | ★★★★★ 效果同 A，但要先改造环境 |
| C. tkinter + ttk | 标准库，零依赖；启动最快 | 控件外观老旧，圆角/阴影/毛玻璃几乎做不了；高亮与划线要用 `Text` tag 或 Canvas 逐字定位，"笔记本纸感"很难达成；动画需手写 after 循环 | 无 | ★★☆☆☆ 视觉目标（纸感、笔触）基本放弃 |
| D. pywebview + HTML/CSS/JS | 视觉天花板最高：CSS 可直接实现 `backdrop-filter` 毛玻璃、spring 动画、真实纸张纹理，正好是 `apple-design` skill 的原生语境 | 需装 pywebview（Python 3.8 可用 4.x）；依赖系统 WebView2（Win10/11 一般自带）；Python ↔ JS 双向通信要自己包一层；打包后仍依赖 WebView2 运行时 | pywebview | ★★★★☆ 视觉最强，工程复杂度略高 |
| E. wxPython 4.2.2 | 已安装；原生控件，Windows 上观感"系统味" | 自绘能力弱于 Qt；动画/透明/圆角支持差；文档与社区远不如 Qt | 无 | ★★☆☆☆ |

**结论（默认）**：选 **A. PyQt5**。理由：本需求 70% 的工作量在"自绘纸页 + 手绘标记 + 动效"，这正是 Qt 的强项；而已装环境意味着今天就能跑起来，不必先花时间折腾解释器。若你更看重"极致 Apple 视觉"，选 D，我按 web 方案重写 UI 层（数据/服务层不变）。

## 3. D2 · 数据入库边界（**需要你选择**）

| 方案 | 说明 | 优点 | 缺点 |
| --- | --- | --- | --- |
| **① 仅代码与文档入库**（默认推荐） | `.gitignore` 忽略 `data/`；`StudyBook/`、`StudyRecord/` 入库 | 绝不泄露 Key；仓库干净；单词本可另做每日 zip 备份 | 我的单词本不随 git 同步（换机需手动拷 `data/words.json`） |
| ② 含单词与记录入库 | 只忽略 `settings.json`/`ai_cache.json`，`words.json` 与 `StudyRecord/` 入库 | 换机即恢复、有历史版本、可 diff 单词增长 | 个人词汇数据公开在 public 仓库 |
| ③ 单词书入库、我的单词本私有 | `StudyBook/` 入库，`data/` 与 `StudyRecord/` 忽略 | 折中：共享词库，保护进度 | 记录不随仓库走 |

**默认**：①。若你愿意公开自己的词汇量，选 ② 更省事。

## 5. 无需你拍板的部分（已定）

| 项 | 结论 | 理由 |
| --- | --- | --- |
| HTTP 客户端 | 标准库 `urllib.request` | 零依赖、打包小；封装在 `ai_client.py`，需要时换 requests 只改一个文件 |
| JSON 读写 | 标准库 `json` + 原子替换写 | 数据量小、可读、可 diff |
| YAML 头解析 | 自实现 30 行极简解析 | 避免 PyYAML 依赖；规范里只用到 `key: value` 与逗号数组 |
| 测试框架 | `unittest` | 标准库；服务层是纯函数，够用 |
| 时间处理 | `datetime` + 本地时区 | 日期分节需要本地日期；ISO8601 存 `created_at` |
| 随机 | `random.Random(seed)` 可注入 | 抽背算法要能用固定种子复现（验收 A7） |
| 日志 | `logging` + `%USERPROFILE%\.real_wordbook\app.log`（滚动 1 MB × 3） | 便于排错，且不落仓库 |
| 配置 | 常量在 `app/config.py`；用户偏好 `data/settings.json`；密钥 `~/.real_wordbook/config.json` | 三层分离，密钥永不入库 |
| AI 模型 | `deepseek-flash` + `reasoning_effort=low` + `thinking enabled` + `json_object` | 按你的要求；该模型名现行有效（V4.1-Flash-1017） |

## 7. 风险提示（与决策相关）

1. **Python 3.8 EOL**：新库逐步放弃 3.8。若选 D1-B 或将来要装新库，需要主动升级到 3.12（我可以一并做环境迁移，但属于独立任务）。
2. **Qt5 GPL**：自用无影响；若将来分发闭源二进制，需换 PySide6（LGPL）。
3. **pywebview 路线**：Win 上若 WebView2 运行时缺失，需要装 Evergreen Runtime（几十 MB）。
4. **DeepSeek 计费**：`deepseek-flash` 输入 $0.15/M（缓存未命中）、输出 $0.6/M；单词级缓存后重复查询为 0 成本。
